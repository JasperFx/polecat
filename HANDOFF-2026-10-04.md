Three facts from that work worth not rediscovering:

- **A trigger cannot be guarded with an `IF`** — `CREATE TRIGGER` must begin its batch. Weasel renders
  `DROP TRIGGER IF EXISTS` + `EXEC sp_executesql`, which is also what makes it expressible as a delta.
  Its body is compared against `sys.sql_modules`, so a body SQL Server stores differently from the way
  we declare it reports drift on *every* pass. `generated_schema_script_executes` runs the script twice
  and is where that gets caught.
- **`DocumentTable.AddDeclaredSchemaObjects`' old claim that "no `GO` is needed" was too broad.** The
  line is **expression versus name list**: an index's key columns / `INCLUDE` list / FK columns always
  worked; a filtered index's *predicate*, a check constraint, and a computed column derived from the
  new column all failed with error 207 — and the `ALTER` rolled back with them. Corrected in #717.
- **`IQueryableMember.LocatorSqlType`** now carries the SQL type each locator produces, including the
  #223 rewrite onto an index's computed column. Guessing it is wrong in both directions: too wide puts
  `CONVERT_IMPLICIT` on the column and scans (#363), too narrow silently truncates.

### 2. polecat#720 — mapped `Version`/`Revision` ignored when seeding the expected version

**Highest severity of the filed set: a documented feature that cannot work.** `Version.MapTo(...)` +
`UseOptimisticConcurrency(true)` fails from any session that did not load the document.

- `DocumentSessionBase.StoreForConcurrency` reads `IVersioned` only; `CaptureExpectedRevision` reads
  `ILongVersioned`/`IRevisioned` and defaults to `0`.
- The Weasel seam is **already pinned**: `IDocumentStorage<T>.MappedVersionFor` / `MappedRevisionFor`
  (weasel#590) exist in 9.39.0 and are referenced nowhere here. No cross-repo wait.
- ⚠️ Keep the `Guid.Empty` / `0` rule: those mean "never stored" and must stay **unseeded**.
- **This is the fourth sighting of this one field** (fisher#245, marten#5372, polecat#592, now this),
  so add a fact to `GuidOptimisticConcurrencyCompliance` upstream rather than only fixing it here.

### 3. polecat#723 — vector / full-text / hybrid search ignore the hierarchy discriminator

A sub-class search returns siblings and base-type rows **deserialized as the sub-class asked for**.
`GetProvider` routes a sub-class to its parent's provider, so the search scans the shared table with
no `doc_type` predicate.

- Three bespoke `WHERE` builders is *how* this happened — prefer one shared helper over three patches.
  The soft-delete and tenant predicates are already duplicated across all three and could come along.
- `Query<SubClass>()` already filters correctly, so this is a two-paths-disagree bug in the shape of
  #683.
- `DocumentSearchCompliance` is enrolled and has no hierarchy fact; Marten has the same bug
  (marten#5440). Fix the suite upstream.

### 4. polecat#722 — multi-member `Select()` emits an absent JSON key as explicit `null`

Throws for a non-nullable value type. Reachable whenever a document type gained a property after rows
were stored.

⚠️ **Do not just add `ABSENT ON NULL`** — that is marten#5499, where the naive fix broke a *genuine*
null on `DateOnly?`, trading a throw for a silently wrong value. `JSON_VALUE` cannot distinguish
absent from present-and-null; the issue has a truth table and suggests choosing per member from the
CLR type. Write the failing test from **both** directions before fixing.

### 5. polecat#718 — `AdvancedOperations` drops by catalog sweep, and never drops partition functions

`CompletelyRemoveAllAsync` sweeps `INFORMATION_SCHEMA.TABLES` for `pc[_]%`. Partition functions and
schemes are not tables, so **nothing in the product ever drops them** — six *test* files hand-roll that
teardown, which is the tell. They are database-scoped, so they outlive the schema and are shared
across schemas, which is exactly how this suite isolates itself.

The issue lays out four options; note the clean model-driven drop is **narrower** than today's
behaviour (it would stop removing de-configured and legacy tables). The partition leak is a bug on any
reading of the rule.

### 6. polecat#725 — the `aot-smoke` lane never performs a read

So it cannot catch any of Marten's four AOT failures. "Writes were fine, the first read threw"
(marten#5328) is exactly what a lane that builds-but-never-enumerates reports as green. Five execution
shapes to add; may need splitting into a no-database smoke test and a database-backed AOT test.

### 7. polecat#724 — guard the resilience extension point against replaying a 3960
